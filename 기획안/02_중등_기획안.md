# [중등] 데이터로 판단하는 AI 드론 — 자율 배달 드론 개발 프로젝트

> 대상: 중학생 (1~3학년, 아래 "수준 조절 팁" 참고) · 120분 · 기본 1인 1대
> 공통 사항(교구 가정, 안전 수칙, 운영 방식)은 `00_공통_기획개요.md`를 참고하세요.

## 1. 수업 한눈에 보기

| 항목 | 내용 |
|---|---|
| 핵심 질문 | **"기계는 어떻게 '구별'할까?"** |
| 핵심 개념 | AI는 **데이터 → 기준 → 분류(판단)**를 거쳐 행동한다. 기준을 **사람이 정하면 규칙 기반 AI**, **데이터로 배우면 머신러닝**이다. |
| 코딩 개념 | 조건문(만약·아니면), 반복문, **변수**, 센서 값 비교 |
| 최종 미션 | 📦 **자율 배달 드론**: 장애물을 감지해 피하고, 목적지 색깔을 구별해 스스로 착륙 |
| 산출물 | 센서 측정표, 알고리즘 순서도, 미션 기록지 |

## 2. 학습 목표

1. AI가 센서 데이터를 **기준값과 비교해 분류하고 판단**한다는 것을 설명할 수 있다.
2. **규칙 기반 AI와 학습 기반 AI(머신러닝)**의 차이를 예를 들어 말할 수 있다.
3. 센서 값을 측정하고 기록해서 **판단 기준값(임계값)**을 스스로 정할 수 있다.
4. 조건문·반복문·변수를 써서 **스스로 판단하는 드론 프로그램**을 만들 수 있다.
5. 드론과 AI 기술이 사생활·안전에 주는 영향을 생각하고 자기 의견을 말할 수 있다.

## 4. 단계별 상세

### 4-1. 도입 (0~10분)

- **사례 제시:** 자율주행차의 긴급 제동, 배달 로봇과 드론 배송 (사진이나 짧은 영상)
- **시연:** 앞으로 날던 드론이 **상자 앞에서 스스로 멈추고** 도트 매트릭스에 ⚠를 띄웁니다.
- **발문**
  - "이 드론은 '상자'를 안다고 할 수 있을까요?"
  - "드론은 어떤 **데이터**를 받았고, 어떤 **기준**으로 '멈춰야 한다'고 판단했을까요?"
- **오늘의 미션 공개:** "여러분은 배달 드론 회사의 신입 AI 개발자입니다. 오늘 안에 **자율 배달 드론** 시제품을 완성하세요!"

### 4-2. 언플러그드: 분류 규칙 만들기 vs 예시로 배우기 (10~25분)

**준비:** 동물·과일 그림 카드 묶음 (또는 다양한 색·모양 도형 카드), 모둠별 1세트

| 라운드 | 방법 | 깨닫는 것 |
|---|---|---|
| **R1. 규칙 기반** (6분) | 모둠이 "고양이 카드를 고르는 **규칙**"을 글로 씁니다. (예: 귀가 뾰족하다 + 수염이 있다) → 강사가 **새 카드**(호랑이, 스핑크스 고양이 등)를 보여 주면 규칙이 맞는지 시험합니다. | 사람이 규칙을 정하면 **예외에 약하다** |
| **R2. 예시로 배우기** (6분) | 규칙을 말하지 않고 "고양이 O / 고양이 X" 예시 카드 10장만 보여 줍니다. → 학생들이 새 카드를 맞히고, 어떤 기준으로 맞혔는지 말해 봅니다. | 예시(데이터)를 많이 보면 **스스로 기준을 찾는다** = 머신러닝 |
| **정리** (3분) | 비교표 작성 | 오늘 드론은 **R1 방식(규칙 기반)**이고, 기준값을 **데이터로 정할 것**이다 |

| 구분 | 규칙 기반 AI | 학습 기반 AI (머신러닝) |
|---|---|---|
| 기준은 누가? | 사람이 직접 | 데이터로 기계가 |
| 장점 | 이유가 분명함, 데이터가 적어도 됨 | 복잡한 문제도 풀 수 있음 |
| 단점 | 예외 상황에 약함 | 데이터가 많이 필요, 이유를 알기 어려움 |
| 예 | 오늘의 드론, 자동문 | 얼굴 인식, 번역기 |

### 4-3. 안전·탐색 (25~35분)

- **안전 체크리스트 서명** (공통 수칙 8가지)
- **센서 값 띄우기 실습:** 도트 매트릭스나 앱 화면에 **센서 값을 숫자로** 띄워 봅니다.
  - 손을 앞에 가까이 또는 멀리 → 적외선 센서 값 변화 관찰
  - 색 카드를 바꿔 가며 → 색상 센서 값 변화 관찰
  - ⚠️ 센서 값을 숫자로 볼 수 없으면 "감지됨 / 안 됨"으로 관찰하고, 4-6 데이터 활동은 **감지 성공률 측정**으로 바꿉니다.
- 긴급 정지 실습

### 4-4. 비행 기본기 (35~55분) — 반복문

> ⚠️ 블록 이름은 실제 이글 코딩 앱에 맞춰 수정 예정입니다.

**도전 ① 기본 이동:** 이륙 → 앞으로 50cm → 오른쪽으로 90° 회전 → 앞으로 50cm → 착륙

**도전 ② 사각형 경로 비행: 반복문으로 줄이기**
```
[이륙하기]
[4번 반복하기]
    [앞으로 50cm 가기]
    [오른쪽으로 90° 돌기]
[착륙하기]
```
- **발문:** "블록 10개를 4개로 줄였어요. 반복문이 왜 필요할까요?" "삼각형을 만들려면 무엇을 바꾸면 될까요?"

**도전 ③ (심화) 변수 쓰기:** `한 변 길이` 변수를 만들어 숫자 하나만 바꾸면 사각형 크기가 달라지게 하기

### 4-5. 쉬는 시간 (55~65분) — 배터리 교체

### 4-6. 데이터 활동: 센서 측정 → 기준값 정하기 (65~80분)

> **"AI의 판단 기준은 감이 아니라 데이터로 정한다!"** (비행 없이 진행하므로 안전하고 빠릅니다)

**활동 ① 적외선 센서 측정표** (장애물 거리별 센서 값)

| 장애물과의 거리 | 10cm | 20cm | 30cm | 50cm | 장애물 없음 |
|---|---|---|---|---|---|
| 측정값 1 | | | | | |
| 측정값 2 | | | | | |
| 측정값 3 | | | | | |

→ **"멈춰야 하는 거리"를 정하고 그때의 센서 값을 기준값으로 정하기** (예: 센서 값이 ○○보다 크면 장애물)

**활동 ② 색상 센서 측정표** (색 카드별 센서 값)

| 색 카드 | 빨강 | 초록 | 파랑 | 흰 바닥 |
|---|---|---|---|---|
| 측정값 (R/G/B 또는 색 번호) | | | | |

→ "도착지(빨강)와 바닥을 **구별하는 기준**은 무엇일까?"

- **발문:** "친구와 기준값이 다른 이유는? (조명, 카드 상태, 센서 차이) → 실제 AI도 **환경이 바뀌면 판단이 달라져요**."
- ⚠️ 이글 드론의 색상 센서가 숫자 값을 주지 않고 "빨강·초록" 같은 색 이름만 준다면, 조명을 바꿔 가며 **"10번 중 몇 번 맞게 인식했나" 정확도 측정**으로 바꿉니다.

### 4-7. 최종 미션: 자율 배달 드론 (80~105분)

> **상황:** "고객의 집(빨강 착륙장)까지 물건을 배달하세요. 가는 길에 장애물이 있을 수 있어요. 드론은 스스로 판단해야 합니다!"

**진행 순서**
1. **순서도 먼저 (5분):** 활동지에 알고리즘 순서도를 그리고 강사에게 확인받습니다. → 확인받으면 코딩 시작
2. **코딩·테스트 (17분)**
3. **최종 시연 (3분):** 구역별로 최종 도전 1회

**미션 맵 예시**
```
 [출발] ──→ ··· [장애물 상자] ··· ──→ [빨강 착륙장 = 고객 집]
```

**알고리즘 예시 (의사코드)**
```
이륙
도트 매트릭스에 "→" 표시
반복:
    만약 앞쪽 센서 값 > 기준값(장애물) 이라면:
        멈추기, 도트 매트릭스에 "!" 표시
        오른쪽으로 비켜서 지나가기 (또는 장애물이 사라질 때까지 기다리기)
    아니고 만약 바닥 색깔 = 빨강(도착지) 이라면:
        도트 매트릭스에 "OK" 표시
        착륙하고 반복 끝내기
    아니면:
        앞으로 조금 가기
```

| 단계 | 도전 내용 |
|---|---|
| ⭐ Level 1 | 장애물 없이, **빨강 착륙장을 구별해** 스스로 착륙하기 |
| ⭐⭐ Level 2 | 가는 길에 장애물이 나타나면 **멈췄다가**, 장애물이 사라지면 다시 출발하기 |
| ⭐⭐⭐ Level 3 | 장애물을 **피해서 돌아간 뒤** 배달 완료하기 |
| 🏆 보너스 | **변수**로 배달 시간(또는 반복 횟수)을 세어 도트 매트릭스에 표시하기 |

- ⚠️ 색상 센서가 **앞쪽**에 있으면, 착륙장 대신 "**도착지에 세워 둔 빨강 표지판**"을 인식하게 바꿉니다.
- **디버깅 안내:** 실패하면 "**감지** 문제(센서 값이 이상)인가, **판단** 문제(기준값·조건이 틀림)인가, **행동** 문제(이동 거리가 틀림)인가?" 세 칸으로 나누어 원인을 찾게 합니다.

### 4-8. 공유·윤리·정리 (105~120분)

- **코드 공유 (4분):** Level 3을 성공한 학생 1~2명의 코드를 화면에 띄우고 설명을 듣습니다.
- **윤리 토론 (7분):** 모둠별로 하나를 골라 1분 의견 말하기
  1. "배달 드론이 센서 오류로 사람과 부딪혔다면, 책임은 누구에게 있을까? (개발자, 회사, 사용자, AI)"
  2. "카메라를 단 배달 드론이 아파트 창문 옆을 지나간다면, 어떤 문제가 생길까?"
  3. "오늘 우리 드론은 조명이 바뀌면 판단이 틀렸다. AI를 믿고 쓰려면 무엇이 필요할까?"
- **출구 카드 (4분):**
  - 오늘 드론이 쓴 AI는 규칙 기반일까, 학습 기반일까? 그 이유는?
  - 기준값을 데이터로 정해야 하는 이유를 한 문장으로 쓰기

## 5. 플랜 B로 바꿀 때 (2~3인 1조 1대)

| 구간 | 바뀌는 점 |
|---|---|
| 비행 기본기 | 도전마다 코더 교대 (①·②·③) |
| 데이터 활동 | 역할 분담: **측정자 / 기록자 / 센서 값 읽는 사람**. 조마다 측정을 3회 이상 해서 **평균값**으로 기준 정하기 (개인보다 데이터 질이 좋아짐) |
| 최종 미션 | 조별 순서도 → 역할 분담 코딩. Level 3 이상 목표 |
| 공유 | 남는 시간에 **조별 2분 발표** ("우리 조의 기준값과 그렇게 정한 이유") |
| 평가 | 조별 미션 결과 + 개인 역할 관찰 + 개인 출구 카드 |

## 6. 환경별 운영 (A안 교실 / B안 컴퓨터실)

| 구분 | A안: 교실 + 태블릿 | B안: 컴퓨터실 + PC |
|---|---|---|
| 언플러그드 | 모둠 책상에서 카드 게임 | 자리에서 그대로 진행 (공간 영향 적음) |
| 데이터 활동 | 책상 위에서 측정 | 책상 위에서 측정, PC 화면으로 센서 값 확인이 편리함 |
| 최종 미션 | 구역 4~6개에 미션 맵 설치 | 구역 2~4개 → **순서도를 먼저 확인받은 순서대로 테스트**, 기다리는 동안 "디버깅 3칸 분석표" 작성 |

## 7. 수준 조절 팁

| 대상 | 조절 방법 |
|---|---|
| **1학년 / 코딩 경험 적음** | 도전 ③(변수) 생략. 최종 미션은 Level 2 목표. 순서도 빈칸 채우기 활동지 제공 |
| **2~3학년 / 경험 많음** | 데이터 활동에서 **평균과 여유값(마진)** 개념 추가. 최종 미션 Level 3과 보너스 목표 |
| 빨리 끝낸 학생 | "장애물이 2개일 때도 성공하는 코드" 도전, 친구 디버깅 멘토 |
| 어려워하는 학생 | 강사가 준비한 **Level 1 기본 코드**에 조건 하나만 더하기 |

## 8. 선택형 AI 확장 — "직접 머신러닝 해 보기" (인터넷 가능 시, 20분)

- **넣는 위치:** 최종 미션 Level 3을 보너스로 돌리고 **85~105분** 구간을 조정, 또는 언플러그드 R2를 대체
- **활동:**
  1. 티처블 머신으로 **드론 수신호 분류 모델** 만들기: ✋ 이륙 / ✊ 착륙 / 👉 오른쪽 / 배경
  2. **데이터 실험:** 클래스당 사진 10장일 때와 50장일 때 정확도 비교, 한 사람 손만 학습시켰을 때 다른 사람 손을 잘 맞히는지 확인
  3. 모델 판단 결과에 따라 학생이 해당 드론 프로그램 실행 (⚠️ 직접 연동되면 자동 실행으로 변경)
- **비교 정리:** 드론 센서 판단(**사람이 정한 기준값**) vs 티처블 머신(**데이터로 배운 기준**) → 언플러그드 비교표 다시 보기
- **윤리 연결:** "한 사람의 손만 학습하면 다른 사람 손을 못 알아본다 → **데이터 편향**"
